# E0338: module-level `let` in a library module

Only the program's entry module may have mutable top-level state. A library module (one
that's imported) can only have `const` bindings at the top level, so importing it never
brings hidden shared state with it, and its initialization order doesn't matter.

```ts ignore
// counter.pi, imported by main.pi
let count = 0
export function next(): int { count }
```

Use `const`, keep the state in an object the caller creates, or move the variable into the
entry module. (This example needs two modules, so it isn't checked.)

```ts ignore
// counter.pi
export class Counter {
  public count = 0
  constructor() {}
}
```
