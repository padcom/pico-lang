# E0334: assignment to a `readonly` field outside a constructor

A `readonly` field gets its value in the constructor and keeps it for the object's life.
Code that holds the object can rely on that, so assigning the field anywhere else is an
error.

```ts
class Doc {
  constructor(public readonly title: string) {}
}
const d = new Doc("draft")
d.title = "final"
```

Set the value when constructing the object (or create a new one), or drop `readonly` if the
field really changes.

```ts
class Doc {
  constructor(public readonly title: string) {}
}
const d = new Doc("final")
println(d.title)
```
