# E0339: a cycle in module initialization

Modules may import each other, but their top-level initializers run in one order. When
module `a`'s initializer needs a value from `b` and `b`'s needs one from `a`, one of them
would read a value that isn't initialized yet, so pico rejects the cycle.

```ts ignore
// a.pi
import { B } from "./b"
export const A = 1
export const A2 = B + 1
// b.pi
import { A2 } from "./a"
export const B = A2 * 2
```

Break the cycle: move the shared values into a third module that both import, or compute
one of them in a function that's called later. (This example needs several modules, so it
isn't checked.)

```ts ignore
// base.pi
export const A = 1
// b.pi
import { A } from "./base"
export const B = (A + 1) * 2
```
