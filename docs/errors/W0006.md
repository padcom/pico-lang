# W0006: a function's result is a simple value without `return`

A function's last expression is its result. When that result is a simple value (a variable, a
literal, an operation or a member read), an explicit `return` makes it easier to see what the
function hands back, so the rule asks for one. Calls, `new`, `if`, `match`, `switch`, blocks,
`try`, `await` and closures can stay implicit results. It's on by default; turn it off with
`"lint": { "explicitReturn": false }` in `project.json`.

```ts
function total(prices: i32[]): i32 {
  let sum: i32 = 0
  for (const p of prices) sum += p
  sum
}
println(total([1, 2, 3]))
```

Return the value with `return`:

```ts
function total(prices: i32[]): i32 {
  let sum: i32 = 0
  for (const p of prices) sum += p
  return sum
}
println(total([1, 2, 3]))
```

Reported: variables, numbers, booleans, `null`, strings, templates, array and object
literals, operations (`a + b`, `!x`, `a ?? b`, `c ? a : b`, `x as T`, `x!`, ranges), member
reads (`p.x`) and element reads (`xs[0]`). Arrow functions with an expression body
(`(x: i32) => x + 1`), constructors, setters, generators, functions declared `: void` and
blocks used as values (`const a = { const w = 3; w }`) are exempt.
